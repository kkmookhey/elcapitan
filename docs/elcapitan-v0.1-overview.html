What we built

A remediation control plane—not an agent free-for-all.

El Capitan coordinates scanner intake, live validation, evidence, operational review, approval, and guarded execution. Deterministic code owns state, retries, credentials, scheduling, rollback, and audit; optional models are confined to typed specialist work.

Exact cloud evidence

Service-aware validation—not generic field matching

S3, RDS, security-group, and EBS collectors bind reads to the finding's exact ARN, account, and region. Denied, missing, multiple, mismatched, partial, or malformed responses stay unavailable instead of becoming conclusions.

Transparent priority

Scanner severity is only one signal

Exact asset context can add criticality, exposure, reachability, exploit evidence, runtime dependency, and compensating controls. Each factor and its evidence remain visible to the reviewer.

State-grounded plan

The S3 change cannot quietly expand

The planner selects one aws_s3_bucket_versioning state address, changes only its status, rejects create/delete/replacement and sibling fields such as MFA Delete, and discards the inspected plan artifact.

The complete AWS review contract: confirmed validation, contextual risk, exact state and source digests, deterministic source materialization, Terraform format/init/validate/plan checks, one allowed nested plan change, independent SRE review, a future low-usage window, independently checked rollback, model-diversity policy, and an immutable evidence chain. A separate short-lived ELCAP_PLANNER_AWS_* session is required and ambient profiles, scanner credentials, shared files, and the Azure planner identity are excluded. This package lifecycle is contract tested locally; the checkpoint made no AWS request and grants no AWS execution authority.

Use cases

Useful before the first cloud change.

El Capitan creates value in read-only shadow mode, then supports progressively stronger workflows only where evidence, customer policy, identity, and rollback readiness permit.

USE CASE 01

Validate scanner findings

Turn a long export into a live, evidence-backed picture of what is confirmed, cleared, unavailable, or unsupported.

  • No-write OCSF and Security Hub ASFF preview before import
  • Replay-safe deduplication and exact-asset correlation
  • Bounded read-only Azure and AWS collectors
USE CASE 02

Prioritize a cloud remediation fleet

Rank resource-oriented cases with transparent factors instead of treating scanner severity as the entire business decision.

  • Exact-resource asset-context preview with visible match and gap counts
  • Severity, observed exposure, asset criticality, and compensating controls
  • One score-driving observation with every grouped finding scored independently
USE CASE 03

Prepare an auditable change

Link an admitted finding to one exact Terraform resource and produce a complete review package without modifying the source repository.

  • Conservative literal or state-backed source linkage
  • Real Terraform format, validation, and provider-specific plan-scope gates
  • Independent SRE, window, and rollback reviews
  • Canonical package remains awaiting human approval with execution not started
USE CASE 04

Prove safe execution patterns

For the two supported Azure Storage actions, demonstrate tightly scoped execution with recovery built into the lifecycle.

  • Package-bound approval and durable scheduling
  • Checkpoint, health monitoring, and post-change validation
  • Automatic rollback, certificate, and originator handoff

Honest boundaries

What v0.1 does not claim.

The technical preview is deliberately narrow. These boundaries protect customers from interpreting a validated concept as production authority.

No unattended production remediation

Human approval remains mandatory, and production execution requires separately proven identities, connectors, health contracts, checkpoints, and rollback paths.

No universal remediation engine

The product does not claim generic VM or OS patching, arbitrary application-code changes, or execution for every validated control.

No AWS execution

AWS currently has seven S3, eight RDS, twenty EC2 security-group, and two EBS volume validation controls. Only S3 object versioning supports exact planning and canonical human-review packaging, and no AWS control supports live execution. Validation breadth is not mutation authority.

No public multi-tenant SaaS guarantee

v0.1 is self-hosted. Shared-token interfaces are demonstration and bounded-pilot bridges, not production customer identity.

No complete benchmark coverage

Unsupported services and controls remain visible. Coverage is never inferred from neighboring resource types or related checks.

No inferred business or data sensitivity

Owner, environment, criticality, and data classification must be supplied or visibly marked synthetic. Public networking does not by itself prove reachability, sensitive content, runtime use, or business impact.

No unbounded model autonomy

Optional model workers have strict typed contracts, timeouts, retry budgets, idempotent replay, and circuit breakers. They cannot control workflow state or credentials.

El Capitan is an evidence-bound cloud remediation control plane. This living briefing tracks the current build on the v0.1.0 foundation and intentionally keeps validation, planning, execution, and proof grade separate.
